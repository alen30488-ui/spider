What we find

Vulnerabilities we look for first

Typical issues that cost projects money, customer data and control over their own services.

  • Critical risk

    Bot token in the repository

    A token in the code, Git history or logs gives full control of the bot: broadcasts in your name, reading new messages, fake replies.

  • Critical risk

    Access to other people’s orders (IDOR)

    Changing a number in the URL or request is enough to see other customers’ orders, phone numbers and addresses.

  • High risk

    initData without signature checks

    The Mini App server trusts any user_id in the request — anyone can sign in as another user and spend their points.

  • High risk

    Tampered payment amounts

    The price comes from the interface and isn’t checked on the server — the item can be “bought” for 1 ruble.

  • Medium risk

    Webhook without a secret

    Without a secret_token, anyone who knows the webhook URL can send the bot forged updates.

  • Medium risk

    No rate limits

    Password and code brute-forcing, request spam and heavy queries that take the server down.

  • Medium risk

    Outdated dependencies

    Libraries and CMSs with known vulnerabilities that bots scan for and exploit automatically.

  • Low risk

    Verbose error messages

    Stack traces, software versions and file paths tell an attacker where to look next.
