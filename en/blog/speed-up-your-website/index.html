How to speed up your website: 10 steps

Why a slow website loses customers and how to speed it up: what LCP, INP and CLS mean, how to measure speed with PageSpeed Insights and which 10 steps have the most noticeable effect — from images and fonts to caching and server configuration.

A slow website loses visitors before they even see the first screen — especially on mobile internet. Speed also affects promotion: Google takes Core Web Vitals into account in ranking. The good news is that most problems can be solved without rebuilding the website. Here is how to measure speed and what to do first.

How to measure speed

The simplest tool is Google's PageSpeed Insights. It shows two kinds of data:

  • Real user data — how the website loaded for visitors over the last 28 days. This is what matters for search.
  • A lab test — a one-off check in an emulator. It is useful for finding the causes of problems, but its score “out of 100” is not the main thing in itself.

If the website is connected to Search Console, it has a Core Web Vitals report for all pages at once.

MetricWhat it measuresGood result
LCPWhen the main element of the first screen is rendered: an image or a headingup to 2.5 s
INPHow quickly the page responds to taps and inputup to 200 ms
CLSHow much elements shift during loadingup to 0.1

A metric is considered good if at least 75% of visits are within the threshold.

10 steps to a fast website

  1. Compress images and use modern formats. WebP and AVIF weigh noticeably less than JPEG and PNG at the same quality. Prepare several sizes so that a phone does not download an image meant for a wide monitor.
  2. Do not delay loading the main image. Give the first-screen image a high loading priority and lazy-load the rest so that they load as the user scrolls.
  3. Specify the dimensions of images and blocks. If the browser knows the dimensions in advance, the layout does not “jump” when an image loads — this improves CLS.
  4. Optimize fonts. One or two weights instead of six, the WOFF2 format, only the characters you need — Latin and Cyrillic — and text shown in a system font while the brand font loads.
  5. Remove unnecessary third-party scripts. Chat widgets, multiple analytics counters, social media buttons and pop-ups all add weight. Keep what you need and load the rest after the page has loaded or on user action.
  6. Split your JavaScript. Load only the code for the current page and defer non-critical scripts. Heavy computations at the moment of a tap are the main cause of poor INP.
  7. Enable caching and compression. Static files should be cached in the browser for a long time, and text should be compressed on the server — with Brotli or gzip.
  8. Use a CDN for static assets. If your customers are in different cities, a content delivery network serves images and scripts from the server closest to them.
  9. Speed up the server. A slow server response slows down everything else. Page caching, database indexes, optimizing heavy queries and sometimes moving to more powerful hosting all help.
  10. Check speed continuously. A new banner, a video on the home page or yet another analytics counter quietly slow the website down. Check key pages after every release.

What speeding up gives you

A fast website is not just green numbers in a report. Visitors see products and prices immediately, leave the first screen less often and more often get as far as the request form or the cart. In the Maison Lumi online store, a page loads in 1.2 seconds — together with the new catalog, this helped raise the order conversion rate by 38%.

Speed is also part of technical SEO. We collected the other points worth building in during development in the article “SEO during website development”.

When you need a rebuild

Sometimes speeding up hits the limits of the website's foundation: a heavy template, a website builder with dozens of plug-in scripts, an outdated architecture. Targeted fixes will help, but only so much. If the website needs updating anyway, it makes more sense to build a new one on a modern stack — fast from the start.
